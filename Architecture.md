# Architecture

Describes the codebase as of **2026-10-03** (Phase 3 in progress). Items marked 🎯 are planned.

## Tech stack
| Layer | Choice |
|---|---|
| Framework | Next.js 15.1 (App Router, `next dev --turbo`), React 19, TypeScript 5 |
| Styling / UI | Tailwind CSS 3.4, shadcn/ui (preset `b5d3ACm4e`, style `radix-maia`, base `zinc`), Radix, `lucide-react`, `framer-motion`, `sonner` |
| AI UI | Vercel **AI Elements** (`components/ai-elements/*`: conversation, message, prompt-input, suggestion, shimmer, …) |
| Fonts | Manrope (`--font-sans`, `--font-heading`) via `next/font`; `Outfit` still set on `<body>` (to be reconciled with `design.md`) |
| Database | MongoDB via Mongoose 9 (cached connection, `lib/mongodb.ts`; `MONGODB_URI` required) |
| Identity | Firebase Auth (Google, email/password; phone 🎯) — client side only |
| Session | NextAuth v4, JWT strategy, one `firebase` Credentials provider (`lib/auth.ts`) |
| AI | Vercel AI SDK `ai@7`, `@ai-sdk/react@4`, `@ai-sdk/groq`, model `llama-3.3-70b-versatile`, `zod` schemas |
| External | RapidAPI Booking.com (optional live stays); maps provider 🎯 undecided |

## Auth flow
```
Login/Signup page ──► Firebase (Google popup | email+password)
        │ user.getIdToken()
        ▼
signIn("firebase", { idToken }) ──► NextAuth authorize()  (lib/auth.ts)
        │  verifyFirebaseIdToken → Identity Toolkit REST (accounts:lookup, public API key)
        │  upsert User { firebaseUid, email, name, image } in MongoDB
        ▼
NextAuth JWT cookie (token.id = Mongo User _id)
        ├─ middleware.ts: protects /dashboard, /profile, /itinerary/create, /bookmarks
        ├─ API routes: getSessionUser() from lib/auth.ts
        └─ client: useSession() (AuthButtons, SaveButton, BookingModal, ReviewForm)
Logout: lib/auth-client.ts endSession() signs out of both Firebase and NextAuth.
```

## App flow
```
Browser
  ├─ Server components: / (home), /destinations/[slug] ──► Mongoose ──► MongoDB
  ├─ Client pages: /destinations, /stays, /food, /transport ──► GET /api/* ──► Mongoose
  ├─ /destinations/[slug]  ──► SaveButton → /api/saved · ReviewForm → /api/destinations/[slug]/reviews
  │                          · BookingModal → /api/bookings (Pending)
  ├─ /dashboard ──► /api/bookings · /api/saved · /api/itineraries
  ├─ /itinerary ──► useObject ──► POST /api/generate-itinerary ──► Groq streamObject
  │                                (context from Destination, schema in lib/itinerary-schema.ts)
  │                          └─► POST /api/itineraries (save generated plan)
  └─ /chat ──► useChat(DefaultChatTransport) ──► POST /api/chat ──► Groq streamText
                                   tools: searchDestinations, getDestinationDetails (read-only, Mongo)
All AI routes: lib/ai-guard.ts → login required, GROQ key present, 10 req/min/user (in-memory), prompt ≤ 500 chars.
```

## Data model (MongoDB)
- **Destination**: title, unique slug, descriptions, image/gallery/videos, category, region, location, bestTimeToVisit, thingsToDo, safetyTips, localCulture, soloTravelerFriendly, vibe[], embedded `stays[]`, `food[]`, `transport{howToReach, localTransport[]}`, `reviews[{userId,user,rating,date,comment}]` (one per user, enforced in the API).
- **User**: firebaseUid (unique), name, email (unique), image, role, savedDestinations[→Destination]. 🎯 `preferences` (onboarding), phone.
- **Booking**: userId, destinationId, destinationSlug, destinationName, stayName, price (string), checkIn/OutDate, guests, status (Pending/Confirmed/Cancelled), paymentId. Created as Pending; no payment flow.
- **Itinerary**: userId, title, prompt, plan (Mixed; validated against `lib/itinerary-schema.ts` on save).

## Environment (`.env.local`, see `.env.example`)
`MONGODB_URI`, `NEXTAUTH_SECRET`, `NEXTAUTH_URL`, `NEXT_PUBLIC_FIREBASE_*` (API_KEY, AUTH_DOMAIN, PROJECT_ID, STORAGE_BUCKET, MESSAGING_SENDER_ID, APP_ID), `GROQ_API_KEY`, `RAPIDAPI_KEY` (optional). Missing required vars now fail fast (no fallbacks).

## Known gaps → target
| Gap | Target |
|---|---|
| Phone sign-in; `authorize` requires an email | Firebase phone auth, relax email requirement |
| No onboarding / preferences | `User.preferences` + onboarding page; use in home curation and AI prompts |
| In-memory AI rate limit | Shared store (Redis/Upstash) before multi-instance deploy |
| List APIs load all destinations and filter in JS | Mongo queries + pagination |
| No maps (PRD 7), groups (PRD 11), packages (PRD 10), local guides (PRD 8) | Not started; need product/provider decisions |
| Pages not restyled to new shadcn preset | Phase 4 |
| Runtime untested (no credentials yet) | Manual test after `.env.local` set up |
